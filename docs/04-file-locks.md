# FS-04: Sharing violations и неполный поиск

Приоритет: P1. Источники: FileTextHelper и SearchTool.

Статус: выполнено.

Версия реализации: **1.5.0**. Принято независимым ревью: исходная реализация — в первом раунде, затем шесть дефектов и платформенное гейтирование Windows-only sharing-тестов исправлены и подтверждены в раундах 2–3.

## Дефект

Единственный файл с FileShare.None обрывает search. FileShare.ReadWrite не отменяет чужие ограничения. Отсутствие FileShare.Delete на read handles может мешать атомарному сохранению редактором. Два открытия probe/read создают окно удаления файла.

## Контракт

- Read handles используют FileShare.ReadWrite | FileShare.Delete, когда поддерживается платформой. Write sharing определяется стратегией FS-02, не копируется с read.
- Direct tool: locked файл → file_locked, недоступный по ACL → access_denied, исчезнувший → file_not_found. Системный код/HResult хранить для классификации, не путать любую IOException с lock.
- search при ожидаемой ошибке отдельного файла/директории продолжает работу; result object: matches, truncated, incomplete, skipped_count, skipped. skipped содержит ограниченный список относительных path/reason; skipped_count отражает полный счётчик.
- incomplete=true при lock/access denied/исчезновении/link skip; truncated отдельно обозначает result/budget cap. По пустому matches нельзя заключать отсутствие совпадений, если incomplete.
- Один открытый read stream на probe+decode+search. Ошибка корня не маскируется как успешный пустой поиск.
- Retry только для transient sharing violation: максимум три попытки с 50/100 ms и общим deadline. Можно отказаться от retry в search ради отзывчивости. Hash conflict/access denied не повторять. Mutation after uncertain commit не retry.

## Приёмка

Текущие FileLocksTests (Windows): запертый файл не должен скрывать найденный доступный файл, ответ должен сообщать incomplete и file_locked; контрольная проверка read с чужим FileShare.Read проходит. Fixtures открывают настоящий чужой handle, не только подставляют exception.

Дополнить: rename при собственном открытом read handle; FileShare.Read — replace file_locked; удаление между probe/read; ACL file/directory; lock released before retry; cancellation во время ожидания; несколько locked files и ограничение skipped details. Windows-specific sharing tests отмечены явно; POSIX semantics не объявлять эквивалентными.

Зависимости: FS-05 для error classifier, FS-01 для skipped links, FS-07 для deadlines, FS-09 для shared stream parser.

## Реализованный контракт и границы

Read handles: `FileTextHelper.OpenReadStream` открывает файл с `FileShare.ReadWrite | FileShare.Delete` на поддерживающих платформах; этот же handle используется и `read_file`, и `SearchTool` (probe + decode + search — один открытый stream, окно удаления между probe/read устранено). Write sharing по-прежнему определяется стратегией FS-02 (`NativeAtomicPath`) и с read не копируется.

Классификация: единый `FileErrorClassifier` отображает системную ошибку в `file_locked` / `access_denied` / `file_not_found` по `HResult` (0x80070020/0x80070021, 0x80070005, 0x80070002) и по `Win32Exception.NativeErrorCode`, а не по тексту сообщения. FS-05 (1.6.0) доводит таблицу: `ERROR_PATH_NOT_FOUND` (0x80070003) и `DirectoryNotFoundException` дают отдельный `directory_not_found`, а типы not-found проверяются **до** платформенных таблиц, потому что ENOENT в младших битах не различает отсутствующий файл и отсутствующий каталог; `ERROR_FILE_NOT_FOUND` (2) остаётся `file_not_found`, поэтому skip-коды FS-04 не изменились. Win32-таблица применяется **только на Windows**; на Unix то же поле несёт `errno`, поэтому там используется отдельный `ClassifyUnixErrno`: `EACCES(13)`/`EPERM(1)` → `access_denied`, `ENOENT(2)` → `file_not_found`, всё остальное → `null` (`EPIPE(32)`/`EIO(5)` не становятся lock/access). Разделение платформы сделано параметром `ClassifyForPlatform(..., isWindows)` (не мутабельным глобалом), поэтому маппинг детерминированно тестируется на любом host. Все entry points (`read_file`, `list_directory`, `replace_in_file`, legacy `MutationService`, per-file search) вызывают один `Translate`; `hash_conflict`, `unsupported_encoding`, `target_not_found`, отмена и `PathPolicyException` не переклассифицируются. `list_directory` больше не переписывает нераспознанную ошибку в `file_not_found`: такой код (например `ERROR_DIRECTORY` при передаче пути к файлу) остаётся внутренней ошибкой, а чтение атрибутов каждой entry перенесено под классификацию, чтобы lock/ACL/not-found отдельной entry выходил операционным кодом. Это минимальный prerequisite FS-05: полная таблица кодов и безопасные `details`/correlation id реализованы в FS-05 (версия 1.6.0, [05-tool-errors.md](05-tool-errors.md)); protocol validation формы аргументов относится к FS-05/FS-13. Legacy-методы сохраняют оболочку `-32001` с code до удаления в FS-12.

Retry: `SharingRetry` повторяет только transient sharing violation, максимум три попытки с backoff 50/100 ms и общим deadline 1000 ms; ожидание через `Task.Delay(TimeProvider, CancellationToken)`. Остаток deadline ограничивает саму паузу: ждём `min(backoff, remaining)`, а если `remaining <= 0` — retry прекращается и наружу уходит последняя sharing violation; таким образом суммарное ожидание не выходит за 1000 ms. `access_denied`, `file_not_found`, `hash_conflict` и любой mutation outcome не повторяются; mutation после неопределённого commit не повторяется никогда (FS-02). Search retry не делает — отзывчивость важнее: отдельный залоченный файл попадает в skip. Значения лимитов — внутренние константы; конфигурируемые бюджеты, CLI-настройки и отмена целой операции принадлежат FS-07. **FS-07 уточняет исход (R13):** если причиной исчерпания было `operationTimeoutMs` или peer cancel, наружу уходит классификация FS-07 — `resource_limit` или `cancelled`, — а не последняя sharing violation; правило «последняя sharing violation» сохраняется для собственного потолка retry (1000 ms). Пауза retry входит в `operationTimeoutMs` и прерывается обеими причинами немедленно.

Search result: object содержит `matches`, `truncated`, `incomplete`, `skipped_count`, `skipped`. `skipped` — bounded list (не более 50 записей) с относительным `path` и кодом; каждая запись пишет и `reason`, и `code` с одним значением (контрактное решение пользователя: `reason` канонический FS-04, `code` сохранён для FS-01 baseline). `skipped_count` — полный счётчик, даже когда детали обрезаны. `truncated=true` при упоре в лимит 50 matches **и** при усечении по бюджетам FS-07 (обход или payload); сам по себе он не означает полноту. `incomplete=true` при lock/access denied/исчезновении/link skip, а также при skip по бюджету файла и при усечении по бюджетам FS-07. Ошибка корня (resolve/list) не маскируется пустым успехом — операционная ошибка выходит наружу. Link-коды FS-01 (`symlink_not_allowed`, `path_outside_workspace`, `symlink_dangling`, `symlink_cycle`, `unsupported_reparse_point`, `already_visited`) сохранены. **FS-07 расширяет объект:** `truncation_reason` добавляется, когда результат усечён по причине из закрытого перечисления FS-07 R7 (`search_max_files`, `search_max_directories`, `max_response_chars`, `operation_timeout`); при усечении `truncated` и `incomplete` оба `true`. Причины делятся на два класса (FS-07 R7): **исход** (`operation_timeout`, traversal cap) — первая сработавшая побеждает и не перезаписывается; **выдача** (`max_response_chars`) — применяется только при отсутствии причины исхода. Поэтому «первая сработавшая побеждает» верно не всегда: бюджет payload не отменяет уже выбранную причину исхода. Файл, исключённый по `maxFileBytes`/`maxLineChars`, попадает в `skipped` с `reason=resource_limit` и поднимает `incomplete=true` — тот же канал, что и у lock/access, поэтому неполнота выражается уже принятым способом.

Вид каждой entry определяется атрибутами (`File.GetAttributes`) внутри классифицируемого `try`, а не `Directory.Exists` (которая глотает access-denied/исчезновение). Классифицированная ошибка probe записывается в `skipped` (например `access_denied`/`file_not_found`) **до** проверки `file_mask`, поэтому узкая маска не теряет недоступную или исчезнувшую директорию и `incomplete` не остаётся ложным. Идентичность директории для search открывается вариантом `NativePath.GetDirectoryIdentity(path, preserveNativeError: true)`: на Windows исходный `Win32Exception` сохраняется, поэтому залоченная директория классифицируется как `file_locked`, недоступная — `access_denied`, исчезнувшая — `file_not_found`; policy/write-вызовы (`GetPhysicalDirectoryPath`, `AtomicFileWriter.PhysicalParentKey`) продолжают fail-closed отдавать `path_changed`, а на Unix lock не выдумывается. Резолв корня (`_policy.Resolve(".")`) выполняется **до** `try`, поэтому сбой resolve выходит наружу как `PathPolicyException` (операционный `-32001`); а вот ошибки открытия identity и перечисления (`ListEntries`) корня транслируются через `FileErrorClassifier.Translate`, поэтому ACL-denied/locked root становится операционным `access_denied`/`file_locked`, а не `-32603`; действительно неопознанная ошибка остаётся внутренней.

Границы: POSIX sharing advisory, поэтому Windows lock-семантика не объявляется эквивалентной; на Unix классифицируются только access denied/not found, `file_locked` не выдумывается. BOM-aware probe/decode (UTF-16/UTF-32) остаётся за FS-09: `SearchTool` по-прежнему отбрасывает сырой NUL и читает permissive UTF-8, `SearchEncodingTests` для UTF-16/32 остаются KnownDefect. Настраиваемые бюджеты (`maxRequestBytes`, `maxFileBytes`, `operationTimeoutMs`), bounded frame reader, ping/cancel во время tool и concurrent-read limit — FS-07. Полная таблица ошибок tools и неизменяемые `details` — FS-05. Windows ACL-сценарии проверены на текущем Windows host; Unix ACL/permission lane и Native AOT здесь не исполнялись.

Приёмка: `FileLocksTests` расширен до 25 случаев (Baseline). Используются настоящие чужие `FileStream`/directory-handles и реальные ACL/deny ACE, а не инъекция исключений; детерминированные швы (`SearchTool.AfterProbe`, `SearchTool.BeforeEntryKindProbe`, `SearchTool.BeforeDirectoryIdentity`, `FileService.BeforeReadRetry`, `SharingRetry` с инъектируемыми `TimeProvider`/delay, `FileErrorClassifier.ClassifyForPlatform`/`ClassifyUnixErrno`) заменяют sleep-синхронизацию, watchdog-дедлайны не дают тестам висеть. Регрессионные случаи второго раунда: узкая маска при исчезнувшей/ACL-denied директории (skip до mask), исчезновение директории перед открытием identity (native `file_not_found` вместо `path_changed`), залоченная директория (`file_locked`), ACL-denied/locked root как операционный код вместо `-32603`, `list_directory` по пути к файлу не маскируется под `file_not_found`, Unix errno не читается как Win32-код, и пауза retry ограничена остатком deadline.
