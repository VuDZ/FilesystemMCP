## Общие договорённости

- После завершения и приёмки каждой спецификации в ней явно указывать `Статус: выполнено.` и `Версия реализации: x.y.z.`.

- Настройки — immutable ServerOptions, задаваемые при запуске. Первый аргумент остаётся workspace; новые аргументы имеют форму --name=value. Неизвестные имена, неверные boolean/numeric значения и дубликаты — ошибка запуска в stderr и ненулевой exit code. stdout содержит только protocol frames. Конфигурация не меняется через tools/call.
- allowSymLinks — точное имя boolean-настройки, default true по override пользователя; --allowSymLinks=false включает strict jail без ссылок. True разрешает внешние цели ссылок внутри workspace; прямой outside absolute/../ входной маршрут запрещён в обоих режимах.
- logDirectory — точное имя настройки каталога диагностики: --logDirectory=<path>. Без неё используется пользовательский каталог (не каталог бинарника). Пустое значение и дубликат — ошибка запуска; недоступный каталог (занятое имя, ACL, I/O) — не ошибка: file sink отключается, одно безопасное сообщение в stderr, сервер продолжает работу (FS-06).
- Бюджеты FS-07 — immutable настройки запуска той же формы `--name=value`: `maxRequestBytes`, `maxFileBytes`, `maxLineChars`, `maxResponseChars`, `searchMaxFiles`, `searchMaxDirectories`, `operationTimeoutMs`, `maxConcurrentReads`. Все значения — положительные целые, проверяются на startup; ноль, отрицательное, нечисловое значение, дубликат и неизвестное имя — ошибка запуска в stderr с ненулевым exit code. Клиент не может поднять бюджет через `tools/call`, он может только сузить запрос. Значения по умолчанию, семантика и приёмочная матрица — в [07-resource-budgets.md](07-resource-budgets.md).
- Ошибки выполнения tool: result.isError=true, content[0].text — JSON с code, message и при необходимости безопасными деталями. Ошибки формы протокола/аргументов: JSON-RPC error. Клиент не должен разбирать текст exception.
- Коды FS-05 (`file_not_found`, `directory_not_found`, `file_locked`, `access_denied`, `path_outside_workspace`, `symlink_not_allowed`, `hash_conflict`, `target_not_found`, `file_exists`, `unsupported_encoding`, `binary_file`, `resource_limit`, `cancelled`), их триггеры и семантика `retryable` — в [05-tool-errors.md](05-tool-errors.md); `retryable=true` только для транзиентного `file_locked`. FS-07 расширил триггеры `resource_limit` (бюджеты файла, строки, ответа и дедлайн операции) и сузил `cancelled` (только peer-отмена; сработавший дедлайн — это `resource_limit` или частичный результат, EOF и shutdown ответа не порождают), а также добавил в `details` третье поле `truncation_reason`; полный перечень — в [07-resource-budgets.md](07-resource-budgets.md).
- Для read/list/search результаты — JSON object в text content; при поддержке structuredContent тот же object. Изменение search/list с array на object — изменение контракта, требующее версии и обновления README/client samples.
- FS-12 (1.13.0) сохраняет пять стандартных tools и удаляет прямые custom RPC методы. Запрос с method `read_file`, `create_file`, `replace_in_file`, `list_directory`, `search` или `append_to_file` — JSON-RPC `-32601`, без выполнения. append не реализован; рекомендация удалена из AGENTS.md.sample и README, будущая работа — [backlog.md](backlog.md) B-11. Вызов операций — только `tools/call`.
- Новые публичные error codes, metadata и CLI options документируются вместе с реализацией. Не заявлять поддержку MCP-версий без protocol tests.
- Unicode-пути не перекодируются в ANSI и не нормализуются NFC/NFD автоматически.

## Тесты и порядок реализации

Отдельный проект: ../FilesystemMcp.Tests. [Инструкции запуска и статус покрытия](../FilesystemMcp.Tests/README.md).

Тесты с Status=KnownDefect проверяют желаемое поведение и сейчас могут падать. Они не пропускаются и не ожидают ошибочного поведения. Фильтр Baseline отделяет контрольные проверки. После реализации соответствующей спеки снять KnownDefect у исправленных тестов и расширить покрытие её матрицы; целевой gate — весь проект без фильтра.

Порядок: FS-05/06 → FS-01 → FS-02/03 → FS-04/09 → FS-07 → FS-10/11/12/13 и FS-08 независимо. Параллелизм FS-07 включать после защиты записи FS-02. FS-07 реализован в 1.8.0: `Spec=FS-07` — 88 cases, Baseline — 309 passed из 317, вся приёмка спеки выполнена, независимое адверсариальное ревью проведено и его находки закрыты. FS-08 реализован в 1.9.0: `Spec=FS-08` — 75 cases, все проходят на Windows PowerShell 5.1 и на PowerShell 7 там, где он есть; вся приёмка спеки, включая recovery второго commit, denied permissions и переход `-AllowSymLinks`, выполнена; независимое адверсариальное ревью проведено в трёх раундах (10 + 8 + 4 замечания) и независимая верификация четвёртого раунда подтвердила все четыре исправления (143/143 проверки), после чего закрыты ещё два найденных ею поведения (осиротевший backup, опция без значения); оба прежних KnownDefect-случая закрыты, новых падений нет (Baseline — 383 passed из 391). FS-11 реализован в 1.11.0: `Spec=FS-11` — 44 cases, все проходят; четыре прежних KnownDefect-случая переведены в Baseline, KnownDefect-случаев FS-11 нет; полный прогон — 469 cases: 446 passed, 15 failed, 8 skipped, где все 15 падений — прежние KnownDefect FS-10/12/13 (5+8+2), а внешний тайминговый дефект FS-07 `SearchBudgetTests.SearchThatGenuinelyExceedsTheOperationTimeoutReturnsAPartialResult` (ворклоад укладывается в бюджет, `truncation_reason` отсутствует; воспроизводится не всегда — в финальном снимке `TestResults/fs11-acceptance-44.trx` он прошёл, в прогоне на матрице 468 cases падал; исправление вне FS-11). FS-10 реализован в 1.12.0: `Spec=FS-10` — 34 cases, все проходят; пять прежних KnownDefect-случаев переведены в Baseline (3 кейса теории полного чтения, range с начальной пустой строкой, prefix cap с метаданными), KnownDefect-случаев FS-10 нет; `Status=Baseline` — 487 cases: 479 passed, 0 failed, 8 skipped; `Status=KnownDefect` — 10 cases: 10 failed (только FS-12 ×8 + FS-13 ×2); полный прогон — 497 cases: 479 passed, 10 failed, 8 skipped, падающий набор совпадает с KnownDefect-фильтром; внешний тайминговый дефект FS-07 упал в одном Baseline-прогоне этой правки и прошёл изолированно и в финальных прогонах. FS-12 реализован в 1.13.0: `Spec=FS-12` — 14 cases, все проходят; восемь прежних KnownDefect-случаев переведены в Baseline, добавлено 5 cases; KnownDefect-случаев FS-12 нет; `Status=Baseline` — 500 cases: 492 passed, 0 failed, 8 skipped; `Status=KnownDefect` — 2 cases: 2 failed (только прежние FS-13); полный прогон — 502 cases: 492 passed, 2 failed, 8 skipped, падающий набор совпадает с KnownDefect-фильтром; внешний тайминговый дефект FS-07 в прогонах этой правки не упал. Независимое ревью FS-12 ещё впереди.

Наличие текущих тестов не означает полного покрытия: fault injection, ACL, гонки, cancellation и AOT перечислены в спеках как обязательные дополнительные проверки перед закрытием соответствующего пункта.
